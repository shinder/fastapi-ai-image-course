MediaPipe 手部即時追蹤 — 串流到後端

攝影機影格用 WebSocket 送到後端，由 Python 的 MediaPipe 偵測後把座標傳回來， 骨架一樣由這一頁畫。對照另外兩頁：H02 是一次上傳一張圖，H04 是完全在瀏覽器裡跑。

尚未連線
-- fps 來回 -- ms 伺服器推論 -- ms 影格 -- KB 0 隻手
這一頁真正要教的是 backpressure（回壓）。 如果改用 setInterval 每 50 毫秒硬送一格，只要後端處理不及， 影格就會在 WebSocket 的送信佇列裡無上限累積，畫面延遲會愈拖愈長、到好幾秒都不奇怪， 而且永遠追不回來。這裡的做法是同時只讓一格在路上飛 （in-flight 固定為 1）：收到上一格的結果，才送下一格。 後端愈慢，送得就愈慢，延遲自動穩定在「一個來回」。
另外，看一下 badge 的數字：降低解析度只會省頻寬，不會讓推論變快， 因為模型內部本來就會把圖縮到 192／224 像素。
